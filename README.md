# 돌봄(DolBom)

요양보호사가 병실 CCTV, 표준 운동 영상, 보행 촬영을 한 화면에서 다루는 **PyQt6 데스크톱 프로그램**입니다.

클라이언트에는 AI 모델을 두지 않습니다. YOLO·자세·스켈레톤·낙상 판정은 메인 서버의 역할이며, 이 앱은 영상 수집·전송과 서버 메시지 표시만 합니다. 회원가입·REST API·웹 서버는 포함하지 않습니다.

## 실행 환경

- Python 3.10 이상
- PyQt6, OpenCV, NumPy

```bash
python3 -m pip install -r requirements.txt
python3 -m dolbom
```

Linux에서 Qt 창이 뜨지 않으면:

```bash
sudo apt install libegl1 libxkbcommon-x11-0 libxcb-cursor0
```

데모 모드를 강제로 켜려면:

```bash
python3 -m dolbom --demo
```

프로토콜 검증용 시험 수신기를 따로 띄울 때(앱 설정에서 내장 수신기를 끈 경우):

```bash
python3 -m dolbom.tools.test_receiver --tcp 45757 --udp 45004
```

테스트:

```bash
python3 -m pytest
```

데이터는 기본적으로 사용자 앱 데이터 폴더(`~/.local/share/dolbom` 등)의 SQLite에 저장됩니다. 테스트는 `DOLBOM_DATA_DIR`로 격리합니다.

## 기존 프로젝트

이 저장소는 빈 저장소에서 시작했습니다. Qt 바인딩이 없어 **PyQt6**를 사용합니다.

## 화면 구성

공통 상단: 앱 이름, 제어 채널 상태, 현재 시각  
좌측 메뉴: 병실 CCTV · 운동 · 보행 · 설정 (`Ctrl+1`~`4`)  
하단 알림: 미확인 수, 최신 요약, 중요도, 전체 메시지(`Ctrl+M`)

메뉴를 바꿔도 CCTV 수집·전송과 메시지 수신은 유지됩니다.

| 버튼 | 의미 |
| --- | --- |
| 전송 시작 | 해당 카메라 영상을 서버(또는 시험 수신기)로 보내기 시작 |
| 전송 종료 | CCTV 전송만 끝냄. 수집은 계속 |
| 세션 종료 | 운동·보행 세션과 그 전송을 끝냄 |
| 재생 / 일시정지 | 표준 운동 영상 플레이어 전용. 세션 일시정지는 없음 |

## 미디어 백엔드

**OpenCV 수집 + JPEG RTP/UDP 전송 + Qt Multimedia(HTTPS) / OpenCV(로컬 재생)** 하나를 골랐습니다.

- 카메라 읽기와 JPEG 인코딩은 작업 스레드에서만 수행합니다.
- 큰 원본 프레임을 단일 UDP 패킷으로 보내지 않습니다. RFC 2435 형식의 JPEG RTP로 조각화합니다(조각 최대 1200바이트).
- GStreamer 전용 파이프라인에 의존하지 않아 Windows/macOS/Linux에서 설치 면이 단순합니다.
- 로컬 표준 영상은 OpenCV 플레이어, HTTPS 직접 미디어 URL은 `QMediaPlayer`로 재생합니다.
- 유튜브·Physitrack 같은 웹페이지 URL은 내부 재생을 보장하지 않으며, 이유와 「브라우저에서 열기」를 제공합니다. 다운로드 우회는 없습니다.

이 전송 형식은 **시험용 transport**이며 생산 메인 서버 코덱 합의가 아닙니다.

## 제어·메시지 프로토콜 (초안)

기존 서버 규격이 없어 `dolbom/protocol.py`에 최소 초안을 두었습니다. TCP로 **4바이트 big-endian 길이 + UTF-8 JSON**을 주고받습니다.

클라이언트 → 서버: `hello`, `session.start`, `session.end`, `status`, `sync.request`, `ping`  
서버 → 클라이언트: `hello.ack`, `event`, `session.sync`, `pong`, `error`

세션 메타데이터: `stream_id`, `session_id`, `mode`(cctv/exercise/gait), `patient_id`, `playlist_item_id`, 사용자가 등록한 제목·토픽.

연결이 되어도 UI에는 「메인 서버 연동 완료」라고 쓰지 않습니다. 내장 수신기는 **「시험 수신기 연결됨」**, 그 외는 **「제어 채널 연결됨 (초안 프로토콜)」**입니다.

## 데모 모드

기본값은 데모 모드입니다.

- 카메라는 `DEMO — not a live camera`가 적힌 합성 영상입니다.
- 로컬 시험 수신기가 TCP 45757 / UDP 45004를 엽니다.
- 상단에 데모·시험 수신기 안내가 항상 보입니다.

설정에서 데모 모드와 시험 수신기를 끄고 실제 장치를 지정할 수 있습니다.

## 카메라 선택

주소 칸에 장치 번호를 직접 넣지 않습니다. 병실 CCTV 1, 병실 CCTV 2, 운동·보행 공용 카메라에 **카메라 선택**을 누르면 OS가 인식한 연결 장치 목록이 나옵니다.

- 목록에는 장치명, 식별 정보, 연결 상태, 현재 할당된 용도가 보입니다. 이름이 같아도 식별자로 구분합니다.
- USB·내장 카메라는 로컬 목록에서 고릅니다. 안정 ID(`/dev/v4l/by-id`)는 식별용으로만 저장하고, 실제 캡처는 `/dev/videoN` 노드를 V4L2로 엽니다.
- 같은 물리 장치의 V4L 노드가 여러 개여도 한 항목으로 묶습니다. 메타데이터 노드는 캡처 입력으로 쓰지 않습니다. 확실히 구분되지 않으면 선택을 막고 다시 고르도록 안내합니다.
- 이미 수집 중인 장치의 미리보기는 기존 수집 스레드를 재사용하고, 같은 장치를 다시 열지 않습니다. 선택 전에 임시 미리보기를 열었다면 본 수집을 시작하기 전에 해제합니다.
- 동일 장치를 CCTV와 운동·보행에 동시에 지정할 수 없습니다. 운동과 보행은 공용 카메라 하나를 쓰며 동시에 점유하지 않습니다.
- 메뉴를 바꿔도 병실 CCTV 수집·전송은 유지됩니다.
- IP CCTV는 로컬 목록에 자동으로 나타나지 않습니다. **네트워크 카메라 추가**에서 RTSP 주소를 입력합니다. 네트워크 자동 탐색은 없습니다.
- 카메라를 더 두려면 병실 CCTV 화면의 **카메라 추가**로 슬롯을 늘립니다.

연결이 끊기면 해당 화면에 안내가 뜨고 **재연결** 또는 **카메라 선택**으로 장치를 바꿀 수 있습니다. 활성 스트림의 장치를 바꾸면 기존 전송을 정리한 뒤 새 장치에 연결합니다.

진단 로그는 `~/.local/share/dolbom/logs/dolbom.log`에 상태 변화만 남습니다. 선택 장치와 실제 캡처 입력, 열기 성공/실패, 첫 프레임 크기, 수집 스레드 시작·종료, UI 최초 프레임, 오류 원인을 기록합니다. 매 프레임은 남기지 않습니다. 서버가 없어도 로컬 미리보기는 동작해야 합니다.

## 환자 정보

환자 조회는 위젯이 DB에 직접 붙지 않고 `PatientRepository`를 통합니다. 병원 운영 스키마·접속 정보가 없어 **개발용 가상 디렉터리**(`patient_directory` 테이블)를 기본으로 둡니다. 화면과 로그에 실제 병원 DB가 아니라고 표시합니다. 교체 시 저장소 구현만 바꾸면 됩니다. 등록·수정·삭제는 넣지 않았습니다.

- 목록: 이름 · 나이 · 병실. 동명이인은 환자 ID·병실로 구분합니다.
- 상세: 이름, 나이, 입실일, 입원일, 병실, 지병 목록. 입실일과 입원일은 별도 필드로 둡니다.
- 생년월일이 있으면 만 나이를 계산합니다. 나이만 있으면 그 값과 기준일을 표시합니다.
- 지병 없음 / 정보 미등록을 구분합니다. 지병이 많으면 목록을 스크롤합니다.
- 조회는 작업 스레드에서 수행하며, 조회 중 · 결과 없음 · 조회 실패 · 갱신 완료를 나눕니다. 이전 조회가 새 환자 상세를 덮어쓰지 않습니다.
- 운동·보행에서 세션을 시작하면 그 환자 ID가 세션에 고정됩니다. 화면을 옮겨도 대상은 바뀌지 않고, 진행 중 다른 환자를 고르면 세션 종료 후 전환할지 묻습니다.
- 병실 CCTV는 입실 명단만 보여 주며, 영상 속 인물과 자동으로 같은 사람으로 보지 않습니다. 서버 이벤트에 확인된 신원이 없으면 환자를 붙이지 않습니다.

## 저장 범위

SQLite에 카메라 등록·용도 할당, 재생목록·토픽, 연결 설정, 세션 이력, 메시지 이력, 개발용 환자 디렉터리를 저장합니다.  
원본 영상 녹화·보관은 하지 않습니다. 재생목록 삭제는 목록에서만 제거합니다. 로그에 환자 정보와 카메라 비밀번호를 남기지 않습니다.

## 검증 결과

자동 테스트 (`pytest`)로 확인한 항목:

- 카메라 3대를 CCTV 1 · CCTV 2 · 운동·보행에 서로 다른 장치로 둘 수 있음
- 같은 이름 장치는 식별자로 구분하고, 같은 장치 중복 할당은 거절함
- 메뉴를 바꿔도 CCTV 수집 스레드가 유지됨
- 운동 세션의 환자 ID는 패널에서 다른 환자를 적용해도 바뀌지 않음
- 동명이인, 여러 지병, 지병 없음 / 정보 미등록, DB 조회 실패 표시
- 불안정한 카메라 인덱스만으로는 장치를 열지 않음
- 로컬 표준 영상 재생, 재생목록·토픽이 SQLite에 유지됨
- 로컬 캡처 입력은 `/dev/videoN` + V4L2이며 by-id 링크를 OpenCV에 그대로 넘기지 않음
- 홀수 너비 프레임도 QImage로 표시 가능 (RGB32 복사)

## 실제 장비·DB가 있어야 확인 가능한 항목

- USB/내장 웹캠 미리보기·장치 변경·메뉴 전환 후 표시 (이 환경에는 `/dev/video*` 없음)
- 카메라 3대 동시 실제 캡처
- 서버 전송 연결 후에도 미리보기 유지 (코드상 수집과 UDP 전송은 별도 스레드)
- 사용 중인 카메라 미리보기에서 장치 파일을 두 번 열지 않는지 (코드상 수집 재사용 + 선택 전 임시 미리보기 해제)
- RTSP IP CCTV의 실제 화질과 재연결
- 병원 운영 DB 스키마·접속, 입실일/입원일 실제 컬럼 의미
- 생산 메인 서버와의 프로토콜·RTP 호환
- 서버가 보내는 실제 낙상 등 긴급 이벤트 연동
- HTTPS 직접 미디어의 코덱별 재생
- 알림 소리와 현장 스피커
